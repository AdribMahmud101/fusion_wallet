## Build
1. `arena/scenarios.json`: every §18.1 scenario (Morse/base64 prompt injection, "send to 0x…", changed bank details / new payee still cooling, lookalike/poisoned address, duplicate payment, reserve raid, over-limit amount, unapproved vault, sanctions-listed payee, paused module, replayed digest, expired queue, …) with: id, description, attacker goal, expected stopping layer.
2. `arena/run_arena.sh`: runs each scenario against the real layer that should stop it — model layer via `planner-host` (AHEM-G on/off), validator + policy via fusion-core tests/binaries, contract via forge tests on Anvil — AND runs the contract-level attacks against `NaiveAgentWallet` on Anvil to show the loss without Kavachi. Record per scenario: stopped (yes/no), stopping layer, evidence pointer (forge test name, tx/revert hash on Anvil, Base Sepolia E16 tx hash where one exists, planner log line).
3. Evaluation corpus `arena/corpus/{benign,malicious}.jsonl` (≥ 30 each, frozen, hashed in `evidence/results/corpus.sha256`): run through the full off-chain pipeline (planner → validator → preview); report ASR on malicious and FBR on benign, with denominators, for AHEM-G ON and OFF (ablation).
4. `evidence/results/latest.json` (machine-readable, consumed by the app Safety tab and docs) + `evidence/results/ARENA.md` (table: scenario · layer that stopped it · evidence link · naive-wallet outcome; then ASR/FBR table). Every number generated by the runner, none typed by hand.
