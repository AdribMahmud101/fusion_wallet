# Frozen interface clarifications

- §7.3 requires checking ERC20 return data, but frozen `ISafeMinimal.execTransactionFromModule` only returns a success boolean. The module uses official Safe v1.4.1 `execTransactionFromModuleReturnData`, which internally calls `execTransactionFromModule`, always with value 0 and Operation.Call. This preserves token return data without changing the frozen module interface. See vendored `lib/safe-smart-account/contracts/base/ModuleManager.sol`.
- A concrete immutable deployment needs a constructor, absent from the interface ABI. ABI parity compares every function, event and error exactly and excludes only the concrete constructor ABI entry.
- No shape error exists in the frozen ABI; malformed action shapes use `UnsupportedAction`.
- An owner payment changes the mandate reserve. It invalidates any queue (consuming its nonce) rather than leaving a digest pinned to the previous reserve.
- §7.13 I7's “strictly increases” applies to execution / queue consumption. No-op pause, queue creation and other administrative calls do not increment actionNonce. The invariant also checks global monotonicity.
- Official Safe v1.4.1 source cannot compile under solc 0.8.24 via-IR (Yul stack/memory-guard error). The test dependency uses Foundry's separate `safe-legacy` compiler profile (`via_ir=false`); production module sources are restricted to `via_ir=true`. Tests deploy the unmodified singleton and proxy factory artifacts and perform threshold-two Safe transactions.
- The first two size splits alone remained over EIP-170. Dropping `hashAction` (split 3) contradicts the frozen ABI. Instead the existing stateless `KavachiPolicyLib` also validates action envelopes and computes full-precision share bounds. This keeps the complete frozen module API. The compiler-generated linked-library delegatecalls are the §7.14 size split; Safe operations are always Call, and there is no caller-supplied delegatecall or generic execution surface.
